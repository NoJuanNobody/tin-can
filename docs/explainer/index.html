What is tin-can and what is it like to use?

Long image

A

Answer

tin-can is a planned tool, not working software yet. It is one command-line program that lets your coding agent text, or talk out loud with, an agent on a friend's machine.

  1. You share an address the way you share a phone number; the address is your public key, so there are no accounts.1
  2. Your agent sends through the same program however it is wired in: MCP for Claude Code, plain CLI with --json for shell harnesses, a chat prompt for you.2
  3. Messages are sealed to the recipient and signed by the sender, so the relay in the middle stores only ciphertext.3
  4. The repo holds the design and a phased plan; Phase 0 (scaffold) has not started.4

Applies toRead from the tin-can repo at commit 3cded63 (Oct 2026): README, ARCHITECTURE.md, PLAN.md and research notes. Docs only, no code. Every command and step below is the intended design, not a tested result.

What would one conversation look like?

Diagram structure
  • You you
  • Your Claude Code claude
  • Your tin-can tincanA
  • Blind relay relay
  • Friend's tin-can tincanB
  • Friend's agent friend
  • you → tincanA · id keygen me
  • tincanA → you · your address tc:…
  • you → tincanA · contact add friend tc:…
  • you → claude · say hello to friend
  • claude → tincanA · tincan_send
  • tincanA → relay · sealed, signed envelope
  • relay → tincanB · push ciphertext
  • tincanB → friend · decrypted message
  • friend → tincanB · reply
  • tincanB → relay · sealed reply
  • relay → tincanA · push ciphertext
  • tincanA → claude · reply in inbox
  1. You ↗

    Run cli-anything-tincan id keygen me once; it prints your address, which starts with tc:.

  2. Your tin-can ↗

    Add your friend's address as a contact. The key is pinned on first use and a change raises a loud warning.

  3. Your Claude Code ↗

    Ask in plain words; Claude Code calls the tincan_send MCP tool.

  4. Blind relay ↗

    The relay checks the signature, stores ciphertext for the recipient and pushes it live. It cannot read it.

  5. Friend's agent ↗

    Their side might be Claude Code, opencode, hermes, codex, a script or a local model.

Where does the voice come in?

Voice is an optional layer on top of text messages.5 You hold a push-to-talk key, whisper turns your speech into text, and tin-can sends it with --speak. On the other machine, a message marked speak=true is read aloud by kokoro-say or the friend's own text-to-speech.

The Phase 5 target is that a sentence spoken on one Mac is said aloud by the other agent within 3 seconds.6 That is a goal in the plan, not a measurement.

Behind an address there can also be a runner instead of a live agent: a local Ollama model, a free OpenRouter model, claude -p or any script. The daemon feeds it each inbound message and sends back its reply.7

What keeps two agents from causing trouble?

RiskPlanned guard
Someone pretends to be your friendSigned envelopes; the address is the key; warning when a contact's key changes
The relay reads your messagesMessages are sealed to the recipient; the relay keeps ciphertext only
A message tells your agent to run commandsInbound text is untrusted; agents must not act on it outside tin-can
Two agents reply to each other foreverAgent-to-agent replies count hops and stop at 3
Strangers spam youOnly contacts are accepted by default; the relay limits each sender to 60 a minute

By default an agent only relays what its human says and does not improvise answers.8 The full list is in the safety table.9
